02

系统架构

洗衣管家（打印）→ 虚拟打印机「水洗唛打印助手」→ 文件槽捕获（60ms）→ 截取对齐 + 2.03mm 补偿→ 旋转 90°→ 打印到「水洗唛」→ 归档 + 预览 + 日志

一个后台进程（app/console.py，无窗口、单实例、开机自启）同时提供：① 监视处理管线；② 本地操作页面（仅本机）；③ 每日清理。

三个关键机制（维护时理解这几条即可）

  • 文件槽捕获：虚拟打印机每次任务重写 spool\capture.pdf；服务 60ms 轮询读取完整版本（%PDF / %%EOF 校验）。判重规则为「内容 + 写入时间都相同才算同一版本」——保证同一张唛复打两遍（鞋类常见）也能逐张出纸。
  • 截取对齐：捕获页为 A4，仅截取左上角 [0,0,120,30]mm，并按 shift_mm=[2.03,0] 平移，与旧版式逐像素对齐（偏差 ≤1px）。
  • 每日清理：归档 / 预览默认保留最近 7 天（config.json → cleanup；每天自动执行，支持 cleanup 命令手动执行）。

printerstatus.py 对外接口（v2.2 新增）

  • status(cfg=None, name=None, timeout=PRINTER_CHECK_TIMEOUT) —— 主入口。永不抛异常，失败一律降级为带 error 的字典；内部检测跑在守护线程里，join(timeout)（默认 5 秒）超时即返回「检测超时」，避免驱动 / 打印后台处理程序卡住时拖死操作台每 3 秒一次的轮询。
  • target_name(cfg) —— 目标打印机名（取 print.printer，缺省 水洗唛）。
  • _decode_status(code) / _level(code, installed) —— 状态码 → 中文文本 / 等级（内部用，QA 回归有断言覆盖）。
  • 命令行自检：python -m app.printerstatus [打印机名]。
返回字段说明

levelok（可用）/ warn（工作中，如正在打印）/ bad（不可用）/ error（检测失败或未安装）

ok综合判定是否可用（level != bad）
printers本机可见打印机名列表（排查用）

error仅失败时存在：枚举失败 / 读取失败 / 检测超时

匹配与降级策略：只认完全同名（忽略大小写）——历史版本曾做子串回退，会把虚拟打印机「水洗唛打印助手」误报成物理机「就绪」，属于假可用，已移除，改为在未匹配时给出 similar 供核对。15 个「阻塞类」状态位（暂停 / 错误 / 缺纸 / 卡纸 / 离线 / 不可用 / 缺墨 / 需人工干预 等）命中即 ok=false；「正在打印 / 忙 / 传输中」只算 warn 不算故障。pywin32 缺失、EnumPrinters 抛异常、OpenPrinter 失败分别降级为「未安装 pywin32」「枚举本机打印机失败」「读取打印机状态失败」，接口一律不 500。

运行与维护

日常操作：双击「打开操作页面.cmd」→ 浏览器打开操作页面（状态、虚拟打印机检测 / 修复、打印校准唛、切换打印方向、打开目录、最近处理、日志；v2.2 起还有 本机打印机（真正出纸）状态 与 关键词排除打印 两张卡片，后者改完即时生效、无需重启）。

提示：v2.2 代码更新后需重启服务才生效——先「停止软件.cmd」，再「打开操作页面.cmd」。

操作台接口（/api/status 与 /api/action）

页面每 3 秒轮询 /api/status；所有动作走 POST /api/action，请求体为 {name, arg}。

/api/status 在 v2.1 字段基础上新增三项（v2.2）：

字段内容
printerprinterstatus.status(cfg) 的结果（本机目标打印机状态，字段见 §2）
config_errorConfig.load_error——配置损坏 / 空 / 非法时的中文告警，正常为空串；非空时页面顶部显示红色告警条
skip_print{enabled, keywords}——关键词排除打印的开关与关键词列表（页面用它渲染开关与关键词标签）

/api/action 在 v2.1 动作（calibrate / open_dir / set_rotate / vp_check / vp_install）基础上新增四个动作（v2.2）：

动作参数 arg行为与返回
printer_check无清空打印机状态缓存并强制重新检测；返回 {ok:true, data:<printer 字段>, msg:"本机打印机「水洗唛」：就绪"}
skip_toggle无翻转 skip_print.enabled；写回 config.json 并同步内存配置（即时生效）；返回 {ok, data:<skip_print>, msg}
skip_add关键词字符串去首尾与内部空白后追加；校验空串 / 重复 / 单条 ≤30 字 / 总数 ≤50，非法返回 {ok:false, msg:"…"}；成功返回 {ok:true, data:<skip_print>, msg}
skip_del关键词字符串按规范化后的名字删除；不存在返回 {ok:false, msg:"未找到关键词「…」"}；成功返回 {ok:true, data:<skip_print>, msg}

约定要点：四个 skip_* 动作都遵循「就地改内存配置 → cfg.save() → 失败回滚内存值」，与 watcher / pipeline 共用同一个 Config 实例，因此无需重启即可生效；/api/status 与 /api/action 的异常路径统一返回 200 + 中文提示，不再返回 500。

配置加载的容错约定（重要）

config.json 损坏（非法 JSON / 空文件 / 顶层不是对象）时，Config.__init__ 不抛异常：

  • 把损坏文件另存为 config.json.corrupt-<YYYYmmdd-HHMMSS>.bak（先复制，复制失败再退化为改名），路径记在 Config.backup_path；
  • 用 DEFAULTS 兜底继续运行，后台服务照常启动、状态照常检测；
  • 可读告警记在 Config.load_error（run() 启动时会写一条 WARNING，/api/status 的 config_error 会带上它并在页面顶部显示告警条）。

这是 v2.2 的核心修复：此前一次手工编辑漏逗号就让服务启动即崩溃、操作页面「连接中断」、所有状态检测失效。

故障排查速查

现象处理
打印后没出标签检查打印时选的打印机是否为「水洗唛打印助手」；打开操作页面看状态；查 out\logs 当天日志
打印机不见了双击「安装虚拟打印机.cmd」重装；或操作页面 →「虚拟打印机」检测 / 修复

构建踩坑沉淀（重构时注意）

① .cmd 必须 CRLF 行尾（LF + 中文 + chcp 会被解析出杂音命令）；② .ps1 需 UTF-8 BOM；③ 内嵌运行时 ._pth 需含 ..；④ 卸载清理的进程匹配先限定 Name=python*；⑤ 静默测试：/VERYSILENT /TASKS="" /DIR=... /LOG=...。

已知限制与注意事项

  • 旋转方向：出厂默认顺时针（cw），可在操作页面「打印方向」切换（即时生效并写回 config.json）。
  • 单实例：同机只允许一个服务实例；多份安装共用同一虚拟打印机与自启项（会指向最新安装的目录）。
  • 捕获为覆盖式写入：60ms 轮询已实测连打不丢；极端情况可按 out\archive 记录补打。
  • 旧通道兜底：pdfFactory 自动保存目录仍被监听（兼容历史流程）。
  • 卸载：会移除程序、自启与虚拟打印机；out\ 数据目录保留（如需彻底清理手动删除）。
  • 安装包未做代码签名：新机器首次运行可能有 SmartScreen 提示（选择「仍要运行」）。
  • 非本项目提示：计划任务「XQY-XYGJ-Bridge」为照片同步项目遗留（指向已不存在的脚本），与本工具无关，请勿改动，待照片项目处理。
